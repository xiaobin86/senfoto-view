# LidarView 支持的雷达硬件规范

本文档沉淀 LakiBeam 与 Senfoto 008 两款雷达的硬件数据包规范，供后续维护、新增型号或调试时快速查询。

---

## 1. LakiBeam（RichBeam LakiBeam1）

### 1.1 基本信息

| 项目 | 值 |
|------|-----|
| 厂商 | RichBeam |
| 型号 | LakiBeam1 |
| 线数 | 单线（水平扫描） |
| 默认端口 | 2368 |
| 数据包大小 | 1206 bytes |
| 距离分辨率 | 0.001 m（1 mm） |
| 水平角分辨率 | 0.01° |

### 1.2 MSOP 数据包结构

| 区域 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| 数据块 0..11 | 0 | 12 × 100 = 1200 bytes | 每个数据块 100 bytes |
| 时间戳 | 1200 | 4 bytes | 小端 uint32，单位 us |
| 预留 | 1204 | 2 bytes | / |
| **合计** | | **1206 bytes** | |

### 1.3 数据块结构（100 bytes）

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| Flag | 0 | 2 bytes | `0xEEFF`（小端读取） |
| Azimuth | 2 | 2 bytes | 小端 uint16，×0.01° |
| 通道数据 | 4 | 16 × 6 = 96 bytes | 每个点 6 bytes |

### 1.4 通道数据结构（6 bytes）

| 字段 | 长度 | 说明 |
|------|------|------|
| Distance | 2 bytes | 小端 uint16，×0.001 m |
| RSSI / Intensity | 1 byte | 回光强度 |
| 预留 | 3 bytes | / |

### 1.5 坐标计算

LakiBeam 为单线水平雷达，点云位于 x-y 平面：

```text
azRad = radians(azimuth)
x = distance * cos(azRad)
y = distance * sin(azRad)
z = 0
```

### 1.6 帧分割

当连续数据块的 azimuth 从高值跳变到低值（跨越 0°）时，认为完成一圈，触发 `SplitFrame()`。

## 2. Senfoto 008

### 2.1 基本信息

| 项目 | 值 |
|------|-----|
| 厂商 | Senfoto |
| 型号 | 008 |
| 线数 | 48 线（`Lidar_model=0x01`）/ 96 线（`Lidar_model=0x02`） |
| 默认端口 | 8089 |
| 不含 UDP 头数据包大小 | 1248 bytes |
| 含 42 bytes UDP 头数据包大小 | 1290 bytes |
| 距离分辨率 | 0.01 m（raw / 100） |
| 水平角分辨率 | 0.01° |
| 垂直角间隔 | 约 0.95°（96 线）/ 约 1.9°（48 线） |

### 2.2 数据包整体结构

| 区域 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| Header | 0 | 42 bytes | 包头 |
| Body | 42 | 1184 bytes | 8 × 148 bytes 数据块 |
| Tail | 1226 | 22 bytes | 帧尾 |
| **合计** | | **1248 bytes** | |

### 2.3 Header（42 bytes）

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| pkt_head | 0 | 4 bytes | 固定 `00 00 53 46` |
| Rev0 | 4 | 8 bytes | 预留 |
| pktcnt | 12 | 4 bytes | 包循环计数 0-65535 |
| Rev1 | 16 | 4 bytes | 预留 |
| timestamp | 20 | 10 bytes | 6 bytes 秒 + 4 bytes 微秒，小端 |
| Rev2 | 30 | 1 byte | 预留 |
| Lidar_type | 31 | 1 byte | `0x81` = 008 |
| Lidar_model | 32 | 1 byte | `0x01`=48线，`0x02`=96线 |
| Rev3 | 33 | 9 bytes | 预留 |

### 2.4 Body 数据块（148 bytes × 8）

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| Flag | 0 | 2 bytes | `0xEEFF`（小端读取） |
| Azimuth | 2 | 2 bytes | 小端 uint16，范围 0-36000，×0.01° |
| Channel 1..48 | 4 | 48 × 3 = 144 bytes | 每个通道 3 bytes |

### 2.5 通道数据结构（3 bytes）

| 字段 | 长度 | 说明 |
|------|------|------|
| Distance | 2 bytes | 小端 uint16，`distance_m = raw * 0.01` |
| Intensity | 1 byte | 0-255 |

### 2.6 48 线与 96 线数据组织

#### 48 线单回波（`Lidar_model=0x01`）

- 每个数据块包含全部 48 个通道。
- 8 个数据块对应 8 个不同水平角。
- 激光 ID 0..47 直接对应该数据块内的通道 0..47。
- 垂直角表见 2.8 节。

#### 96 线单回波（`Lidar_model=0x02`）

- 数据块按对组织：`(0,1)`、`(2,3)`、`(4,5)`、`(6,7)`。
- 每对共享同一个 Azimuth。
- 数据块 0 / 2 / 4 / 6：通道 0..47 → 激光 ID 0..47。
- 数据块 1 / 3 / 5 / 7：通道 0..47 → 激光 ID 48..95。
- 每对产生 96 个点，整个数据包 4 个水平角 × 96 线 = 384 个点。

#### 96 线双回波

- 文档说明 Azimuth1~Azimuth4 相同。
- 当前实现按单回波处理（只取前两个 block 作为一个 96 线 sweep），双回波拆分留给后续扩展。

### 2.7 Tail（22 bytes）

| 字段 | 偏移 | 长度 | 说明 |
|------|------|------|------|
| Rev0 | 0 | 4 bytes | 预留 |
| 产品类型 | 4 | 1 byte | `0xa5`=SF，`0xb6`=TREX，`0xc4`=TERO，`0x81`=008 48线，`0x82`=96线 |
| 回波类型 | 5 | 1 byte | `0xa5`=最强回波，`0xa6`=第一回波，`0xa7`=最远回波，`0xb6`=双回波 |
| Rev1 | 6 | 16 bytes | 预留 |

### 2.9 坐标计算

```text
azRad   = radians(azimuth)
elRad   = radians(vertical_angle[laser_id])
x       = distance * cos(elRad) * cos(azRad)
y       = distance * cos(elRad) * sin(azRad)
z       = distance * sin(elRad)
```

### 2.10 帧分割

与 LakiBeam 类似：当连续数据包的 Azimuth 从高值跳变到低值（跨越 0°）时触发 `SplitFrame()`，完成一圈点云输出。

### 2.11 DIFOP 产品信息协议

除 MSOP 点云数据包外，雷达还会发送 DIFOP 产品信息包（长度约 1248 bytes），包含转速、IP、MAC、固件版本、标定数据、温度、电压等。当前 Senfoto008 插件未解析 DIFOP，仅解析 MSOP 点云数据。
